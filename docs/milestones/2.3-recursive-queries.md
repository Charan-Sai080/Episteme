# Milestone 2.3: Recursive Graph Traversal (The Query Engine)

## Goal
Implement advanced SQLite Recursive CTEs to enable graph-walking, answering deep architectural questions for AI agents.

## Architecture Rules
* Do not load the entire `edges` table into Java memory. Perform the traversal *inside* the SQLite engine using `WITH RECURSIVE`.
* All queries must use prepared statements.
* Results should be returned as structured DTOs (Data Transfer Objects).

## Granular Sub-Milestones

### [x] 2.3.1: DTOs & Service Scaffolding
- Define a `GraphNodeDTO` (Record) representing a traversed node (symbol info + depth + edge type).
- Create `GraphQueryDao.java` (Database Layer).

### [x] 2.3.2: Downstream Impact Traversal (Forward Propagation)
- Implement `findDownstreamImpact(long sourceSymbolId, int maxDepth)` in `GraphQueryDao`.
- Use `WITH RECURSIVE` CTE to walk `CALLS`, `READS`, `WRITES` edges forward.
- Guard against infinite loops/cycles in the CTE.

### [x] 2.3.3: Upstream Dependency Traversal (Backward Propagation)
- Implement `findCallers(long targetSymbolId, int maxDepth)` in `GraphQueryDao`.
- Use `WITH RECURSIVE` CTE to walk `CALLS`, `EXTENDS`, `OVERRIDES` edges backward.
- Ensure performant index usage.

### [x] 2.3.4: Integration Testing
- Write `GraphQueryDaoTest.java`.
- Insert dummy symbols and multi-hop cyclic edges.
- Verify that `maxDepth` and cycle prevention work flawlessly.
